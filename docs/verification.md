Работающий локальный Docker-сайт: http://localhost. Панель: http://localhost/admin. Логин `editor`, пароль — локальный игнорируемый файл `.local/admin-password.txt`. Вспомогательные Vite/Django-серверы после проверки остановлены; Docker-сервисы оставлены работающими.

Backend-тесты покрывают разделение черновика/публикации, конфликт редакций, права, CSRF, ротацию refresh и отзыв при logout, проверку согласия, rate limit заявок, валидацию медиа и S3-политику. Браузерные сценарии проверяют cookies и выбор города, поиск каталога, отправку заявки, вход редактора, загрузку фотографии, сохранение черновика, preview, публикацию и восстановление исходного заголовка/баннера.

Повторная проверка редактора охватывает текст, шрифт и цвет главного заголовка после сохранения и публикации; общий шрифт и акцентный цвет; создание, перестановку, скрытие и удаление секций; загрузку фотографии и настоящего WebM с проверкой декодирования; яркость и насыщенность медиа; отображение видео с постером во всех 11 типах секций. Отдельные сценарии проверяют объяснение отказа при загрузке SVG, переходы внутри предпросмотра без потери черновика, отключение отправки заявок в предпросмотре, восстановление после конфликта версий и повторный вход после выхода с несохранёнными правками. Несколько секций преимуществ не дублируют главный заголовок.

Исправлена синхронизация редактора: кешированный ответ старой версии больше не откатывает сохранённый документ. Неудачная загрузка серверной версии сохраняет локальные изменения; успешная явно заменяет их. Общий компонент медиа выбирает видео при наличии ссылки, используя фотографию как постер; без видео показывает фотографию. Исходная композиция страницы сохранена.

Видеофайл для браузерного теста создаётся через Canvas/MediaRecorder в памяти. Тесты восстанавливают исходные опубликованный документ и черновик после каждого сценария, но создают тестовые записи загрузок и заявку. Используйте отдельную локальную базу, не рабочую базу клиента. Проверка декодирования в браузере выполнена для WebM в Chromium; это не проверка всех возможных кодеков MP4 и браузеров.

Скриншоты сохраняются в локальном `docs/screenshots/` (папка исключена из Git). Снимок референса получен отдельно, фотографии и порядок блоков проверены визуально. Ошибочная фотография портфолио заменена на изображение объекта из соответствующего блока референса.

Удалённый репозиторий опубликован: [zephyr363/terraklink](https://github.com/zephyr363/terraklink). В первом [Verify для commit 5c556fe](https://github.com/zephyr363/terraklink/actions/runs/38639259415) job `api` завершился успешно; сборка, unit-тесты, npm audit и браузерные сценарии job `web` прошли, но завершение web задержалось на сохранении кеша uv. В workflow отключено кеширование uv для web и добавлен лимит 15 минут на каждый job. Это не отключает ни одну проверку: Python-зависимости по-прежнему устанавливаются через `uv sync --frozen`.

Обновлённые правила и настройки CI переданы в [PR №1, dev → main](https://github.com/zephyr363/terraklink/pull/1). Перед слиянием проверяются завершённые успешные jobs `api` и `web` для текущего head-коммита PR. Актуальные удалённые результаты и состояние слияния доступны в PR и [GitHub Actions](https://github.com/zephyr363/terraklink/actions).

Репозиторий публичный, серверная защита `main` по решению владельца не включена. Перенос изменений через PR после CI — правило работы команды. Промышленное размещение не выполнялось: инфраструктура клиента не указана. Проверка стандартов доступности и юридических процессов не является завершённой сертификацией — см. `compliance.md`.

Новые сценарии проверяют выбор RU/KZ и его сохранение после перезагрузки, казахские формы и юридические страницы, отдельное редактирование и публикацию KZ без изменения RU, блокировку неверных данных компании до API-запроса. Backend отклоняет дубликаты ID в переводе, некорректные контакты и повреждённые URL; тесты имитируют IntegrityError с откатом транзакции и OperationalError с ответом 503 без SQL. Штатная форма пользователя TerraKlink Admin показывает ошибку повторного логина; телефон заявки проверяется формой.

Отдельный Docker-проект production QA проверен с DEBUG=0, PostgreSQL, Redis, MinIO, Gunicorn, Nginx и Caddy: HTTP → HTTPS, secure/HttpOnly refresh-cookie, вход редактора и TerraKlink Admin через CSRF, чтение загруженного фото по HTTPS, сохранение и публикация. Для localhost использован внутренний сертификат Caddy, браузерный тест явно доверял ему только в своём контексте. Сертификат публичного домена клиента не выпускался. Проверены белая шапка и оранжевый бренд TerraKlink Admin; просмотрены скриншоты редактора и казахской страницы.

Проверка production env и `check --deploy --fail-level WARNING` прошла с двумя намеренными исключениями HSTS (описаны в `deployment.md`). Проверено преобразование лимитов Nginx: 4/8 MiB → 9 MiB на запрос, включая значения с ведущим нулём. Скрипт резервирования создал непустые PostgreSQL/MinIO-копии и маркер COMPLETE. После обновления локального сайта подтверждено совпадение документов, истории, заявок, записей медиа и объектов MinIO с состоянием до пересборки. При штатной работе проект рассчитан на VPS с Docker Compose; инструкции находятся в `deployment.md`.
