# Правила работы с проектом

## Git

- `dev` — ветка разработки. Все дальнейшие изменения и коммиты по этапам выполняйте в `dev`; перед началом работы проверяйте текущую ветку и при необходимости переключайтесь на `dev`, сохраняя незакоммиченные изменения.
- `main` — ветка стабильных релизов. Не ведите разработку и не создавайте рабочие коммиты непосредственно в `main`. Переносите в неё проверенные изменения из `dev` только в рамках явно запрошенного владельцем релиза.
- Удалённый репозиторий: `https://github.com/zephyr363/terraklink`, приватный. Изменения в `main` должны проходить через pull request с успешными проверками CI `api` и `web`. GitHub пока отклонил серверную защиту приватной ветки из-за тарифа; после подключения Pro необходимо включить обязательные PR, обе проверки с актуальной базовой веткой и применение правил к администраторам. До подтверждения через API не считайте защиту активной и не используйте прямой push в `main`.
- По запросу владельца фиксируйте дальнейшие изменения отдельными коммитами по завершённым этапам. Сообщение коммита должно описывать конкретное изменение.
- До каждого коммита проверяйте staged diff и список файлов. Запускайте проверки, соответствующие изменённому коду; результаты указывайте в сообщении пользователю.
- До каждого коммита выполняйте `uv run --frozen scripts/check_staged_secrets.py` и `git diff --cached --check`. Проверка секретов анализирует именно содержимое индекса Git и не выводит значения секретов.
- Не коммитьте секреты, реальные пароли, `.env`, `.local`, базы данных, загруженные пользовательские файлы, резервные копии и локальные артефакты. `.env.example` содержит только placeholders; пароли в тестах — только явно тестовые значения.
- Не отправляйте изменения в удалённый репозиторий без авторизации владельца. Не изменяйте чужие коммиты и не выполняйте разрушительные Git-команды без отдельного запроса.

## Зависимости

- Python-зависимости устанавливайте и обновляйте через uv. Сохраняйте `pyproject.toml` и `uv.lock` вместе.
- Для frontend используйте npm; сохраняйте `package.json` и `package-lock.json` вместе.

## Требования проекта

- Следуйте композиции и визуальному стилю референса likolorpro.ru, без самостоятельной смены дизайна.
- Рабочая страна — Казахстан. Текущие контакты и материалы демонстрационные.
- Объясняйте назначение изменений и существенные ограничения. Архитектура и запуск описаны в README.md и docs/.
